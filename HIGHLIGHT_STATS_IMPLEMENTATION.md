# Highlight Statistics and Fallback Prevention - Implementation Summary

## Problem Statement

There was a bug where fallback chunk highlights were being added even when exact matches had already been identified for the same phrase. This occurred when:

1. A phrase appeared in multiple chunks
2. The first chunk found an exact match via `page.search_for()`
3. A subsequent chunk matched the phrase via fuzzy matching but failed the exact search
4. The subsequent chunk would add fallback highlights despite exact matches already existing

This resulted in:
- Inflated fallback statistics
- Mixed highlighting methods for the same phrase (both yellow exact matches and blue fallback chunks)
- Misleading metrics about highlighting accuracy

## Solution Implemented

### 1. Phrase-Level Buffering

For each phrase we now collect two temporary lists while scanning chunks:
- `phrase_exact_locations` – precise rectangles generated by `page.search_for()`
- `phrase_fallback_locations` – chunk- or page-level rectangles produced by fuzzy matches

Only after all chunks have been processed do we decide which list to keep. Exact matches are always preferred; fallback rectangles are only retained when no exact matches were found anywhere for that phrase.

### 2. Fallback Prevention Logic

Because fallback highlights are buffered separately, we simply skip committing them when `phrase_exact_locations` is non-empty. This keeps phrase-level highlights consistent without needing per-phrase state flags.

### 3. Statistics Tracking

Added comprehensive statistics tracking using `highlight_stats` dictionary:
- Tracks count for each highlight method
- Updated at the point where each highlight is added
- Provides accurate metrics about matching success rates

## Benefits

1. **Accurate Statistics**: Now provides precise metrics on highlight method usage
2. **No Duplicate Fallbacks**: Prevents adding chunk-level highlights when exact matches exist
3. **Better Visibility**: Logs provide clear insight into matching performance
4. **Foundation for Optimization**: Statistics enable data-driven improvements to exact match rates

## Testing

Manual reasoning and ad-hoc simulations confirm that fallback lists are discarded whenever at least one exact span is identified. (Dedicated automated coverage still recommended.)

## Next Steps

With these statistics now available, future improvements can focus on:
1. Increasing exact match percentage by improving text normalization
2. Handling hyphenation and ligatures better
3. Expanding search with text variants (ASCII quotes, dehyphenation, etc.)
4. Word-level fallback instead of full chunk highlighting

The statistics will provide immediate feedback on which optimizations are most effective.
