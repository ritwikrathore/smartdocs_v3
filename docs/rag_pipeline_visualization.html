✂️ Adaptive Sentence-Based Chunking

Documents are split into semantically meaningful chunks using our AdaptiveSentenceChunker. Unlike fixed-size chunking, we respect sentence boundaries and adapt chunk size based on content density. This ensures chunks are coherent and don't cut off mid-sentence.

Chunking Parameters
Parameter Value Purpose
Min Characters 450 Minimum chunk size for meaningful context
Max Characters 900 Maximum chunk size to avoid embedding dilution
Min Sentences 3 Ensure sufficient semantic context
Max Sentences 8 Cap to maintain chunk relevance
Overlap Ratio 20% Sentence overlap for context continuity

📋 Metadata Extraction & Bounding Boxes

Each chunk is enriched with hierarchical metadata (Article/Section structure) and bounding box coordinates from the original PDF. The bounding boxes are critical for highlighting - they tell us exactly where on the page the chunk text appears.

Why Embed Metadata?

We prepend hierarchical metadata to chunk text before embedding. This helps the model understand document structure and improves retrieval when queries reference specific sections.

🔍 Hybrid RAG Retrieval (BM25 + Semantic)

We use a hybrid retrieval strategy combining lexical (BM25) and semantic search. BM25 excels at exact keyword matching while semantic search captures meaning. Scores are normalized and combined using configurable weights.

Retrieval Configuration
Parameter Value Description
Candidate Pool 25 Initial candidates retrieved before reranking
Final Top-K 15 Chunks sent to LLM after reranking
BM25 Weight 0.5 Weight for lexical matching
Semantic Weight 0.5 Weight for embedding similarity

📊 Cross-Encoder Reranking

The top 25 candidates from hybrid retrieval are passed through a cross-encoder reranker (Databricks API). Unlike bi-encoders, cross-encoders jointly process the query and document together, producing more accurate relevance scores at the cost of higher latency.

🤖 LLM Analysis with Grounded Citations

The reranked chunks are formatted with their metadata and sent to the Databricks LLM (databricks-llama-4-maverick). The LLM is instructed to answer the query using only information from the provided chunks and cite supporting quotes verbatim.

LLM Prompt Structure
SYSTEM: You are a document analyst. Answer based ONLY on the provided document excerpts. Cite supporting phrases exactly. USER: Question: What are the default interest provisions? --- DOCUMENT EXCERPTS --- CHUNK_INDEX: 42 CHUNK_ID: chunk_42 LOCATION: Article II - Section 2.07 - Default Rate Interest PAGE_NUMBER: 6 TEXT: Upon the occurrence of any Event of Default, the interest rate shall increase by 2.00% per annum... CHUNK_INDEX: 43 ...
Expected JSON Response
{ "analysis_summary": "The agreement specifies that upon...", "supporting_quotes": [ "interest rate shall increase by 2.00% per annum", "default rate applies to all outstanding amounts" ], "analysis_context": { "chunks_used": [42, 43], "confidence": "high" } }
📝
Verbatim Quotes Required

LLM must quote exact text from chunks - this enables verification later

🔗
Chunk Index Reference

Each chunk has a unique index - LLM can reference which chunks it used

✅ Citation Verification

The verify_and_locate_phrases() method extracts all supporting quotes from the LLM response and verifies they actually exist in the source chunks. We use fuzzy matching (thefuzz library) to handle minor variations from LLM paraphrasing.

🖍️ PDF Highlighting & Annotation

Finally, verified phrases are highlighted in the PDF using PyMuPDF's annotation API. We try multiple search strategies to find the exact location within the chunk's bounding box region, then fall back to highlighting the entire chunk if needed.

Highlight Method Priority
Priority Method Description
0 exact_*_search Exact text match with various normalizations
1 fuzzy_span_match Sliding window fuzzy match within chunk
2 cross_page_fuzzy_match Match spans adjacent page boundary
3 fuzzy_chunk_fallback_individual Highlight individual chunk bboxes
4 fuzzy_chunk_fallback Highlight combined chunk region

Key Insight

The process_file_wrapper function orchestrates the entire pipeline. It's the single entry point that coordinates document parsing, chunking, embedding, and caching—ensuring all downstream steps have consistent data.

Using PyMuPDF for parsing gives us access to both text content and precise coordinate data from the very first step.
